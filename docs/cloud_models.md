# Memilih model layanan cloud

Cloud computing menyediakan sumber daya komputasi lewat jaringan dan biasanya memungkinkan kapasitas berubah mengikuti kebutuhan. Lima karakteristik esensial NIST adalah on-demand self-service, broad network access, resource pooling, rapid elasticity, dan measured service. Karakteristik ini membantu menilai sebuah layanan lebih tepat daripada sekadar melihat nama produknya. Sebagai contoh, server virtual dan aplikasi web yang diakses lewat internet sama-sama cloud, tetapi tanggung jawab pengguna berbeda jauh.

Pada Infrastructure as a Service (IaaS), penyedia mengelola fasilitas fisik dan lapisan virtualisasi. Tim aplikasi tetap memilih sistem operasi, memasang patch, menjalankan runtime, mengatur jaringan aplikasi, dan melindungi data. IaaS memberi kendali tinggi, tetapi beban operasi juga tinggi. Mesin virtual adalah contoh yang mudah dipahami. Ketika tim harus memilih distribusi Linux, membuka port, dan memperbarui paket keamanan sendiri, mereka masih memegang banyak tanggung jawab.

Platform as a Service (PaaS) memindahkan pengelolaan sistem operasi dan sebagian runtime ke penyedia. Tim biasanya mengirim kode, memilih konfigurasi, dan mengelola data. Vercel untuk aplikasi web menunjukkan model yang mendekati PaaS: Git push dapat memicu build dan deployment, sementara tim tetap harus mengatur environment variables dan menjaga kode aman. Label layanan bukan hukum mutlak; satu produk dapat menggabungkan beberapa model. Diskusikan batas tanggung jawab dari fitur yang benar-benar dipakai.

Software as a Service (SaaS) menyediakan aplikasi yang langsung dipakai pengguna akhir. Pengguna tidak mengelola server maupun runtime aplikasi. Mereka masih perlu mengelola akun, kontrol akses, data yang dimasukkan, dan kepatuhan penggunaan. Backend as a Service (BaaS) menyediakan kemampuan backend siap pakai, seperti database, autentikasi, penyimpanan, dan API. Supabase membantu tim mengurangi pekerjaan backend, tetapi schema, grants, RLS, dan retensi data tetap tanggung jawab tim aplikasi. Function as a Service (FaaS) menjalankan fungsi ketika dipanggil; penyedia menangani kapasitas komputasi per eksekusi, sedangkan tim tetap menulis fungsi dan membatasi waktu, memori, biaya, serta akses secret.

Deployment model menjawab siapa yang memakai dan mengelola lingkungan. Public cloud adalah sumber daya yang tersedia untuk banyak pelanggan melalui penyedia. Private cloud didedikasikan pada satu organisasi. Hybrid cloud menghubungkan lingkungan private dan public. Multi-cloud menggunakan lebih dari satu penyedia cloud. Hybrid dan multi-cloud tidak sinonim: organisasi dapat memakai dua public cloud tanpa lingkungan private. Pilihan model harus mengikuti persyaratan data, biaya, latensi, keahlian tim, dan aturan kepatuhan.

Harga pay-as-you-go berarti pembayaran mengikuti pemakaian. Reserved capacity menukar komitmen jangka waktu dengan harga yang lebih pasti. Spot instance dapat lebih murah tetapi dapat dihentikan penyedia ketika kapasitas dibutuhkan. Perhitungan biaya perlu mencakup komputasi, penyimpanan, transfer data, request, dan waktu operasi. Free tier perlu diperiksa ulang sebelum kelas karena kuota dan syaratnya dapat berubah. Arsitektur yang baik punya cara menjalankan demo lokal ketika layanan luar tidak tersedia.
